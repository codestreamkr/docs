# 안전한 작업 흐름

파일 변경은 현재 상태 확인, 범위 확정, 실행, 검증 순서로 진행한다.

## 기본 순서

작은 작업도 같은 흐름으로 닫는다.

```text
현재 상태 확인
→ 요청 범위 확정
→ 필요한 경우 계획 확인
→ 변경 실행
→ 변경사항 확인
→ 테스트·검증
→ 결과 정리
```

## 1. 현재 상태 확인

변경 전에 저장소의 기준과 사용자 작업을 먼저 확인한다.

- 적용되는 지침 파일
- Git 변경사항
- 빌드와 테스트 명령
- 유사 기능의 기존 구현
- 요청과 겹치는 사용자 변경

요청 예시:

```text
회원 등록 흐름을 조사해줘.
관련 파일과 현재 Git 변경사항을 먼저 확인하고 아직 수정하지 마.
```

## 2. 범위 확정

대상, 유지할 계약과 완료 조건을 분명하게 전달한다.

```text
대상: 회원 등록 API
이번 범위: 이메일 중복 검사와 오류 응답
유지 조건: 기존 성공 응답 형식
검증: 관련 단위 테스트
```

정책이나 선택지가 결과를 크게 바꾸면 구현 전에 계획을 확인한다.

## 3. 변경 실행

실행 요청은 수정 범위와 검증 범위를 함께 포함한다.

```text
정리한 범위대로 구현해줘.
관련 테스트를 실행하고 변경한 파일과 결과를 함께 알려줘.
```

## 4. 변경 확인

코드 변경과 실행 결과를 나눠서 확인한다.

- 변경 파일과 실제 diff
- 기존 계약에 미치는 영향
- 실행한 빌드와 테스트 명령
- 성공, 실패와 미실행 사유
- 남은 위험과 사용자 확인 사항

## 실패 처리

실패 원인에 따라 다음 조치를 정한다.

- 명령 실패: 오류 메시지, 실행 위치와 환경 확인
- 테스트 실패: 이번 변경으로 생긴 실패와 기존 실패 구분
- 권한 실패: 필요한 경로와 작업 범위 확인
- 범위 초과: 마지막으로 확인된 범위에서 대상을 축소

## 완료 기준

작업은 다음 상태에서 완료한다.

- 변경 전 현재 상태를 확인했다.
- 대상과 유지 조건이 명확하다.
- 실제 변경 범위를 확인했다.
- 관련 검증을 실행했다.
- 미실행 검증과 남은 위험을 구분했다.
