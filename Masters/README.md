# Masters

Masters는 새로운 기능을 만들거나 어려운 문제를 풀 때 함께할 분야별 전문가다.

Codex와 Claude Code의 실행 방식은 다르지만 Master의 역할, 필요한 입력, 결과 기준은 동일하다. 사용자는 먼저 현재 문제에 맞는 Master를 고르고 자연어로 일을 시작하면 된다.

## 이렇게 시작한다

Master 이름과 현재 문제를 함께 말하면 된다.

```text
잡스형, 회의록에서 담당자별 할 일을 뽑아주는 기능을 만들고 싶어.
첫 번째 버전에 필요한 범위부터 정리해줘.
```

```text
대부님, 주문 목록 조회가 데이터 증가 후 느려졌어.
SQL과 실행 계획을 보고 원인을 찾아줘.
```

```text
로드형, 주문 취소 API를 추가하려고 해.
기존 프로젝트 구조를 먼저 확인하고 구현 범위를 잡아줘.
```

```text
호페형, 기존 PG를 유지하면서 신규 PG를 단계적으로 도입하려고 해.
현재 구조와 전환 시 고려할 상태부터 정리해줘.
```

```text
루신, 이번 주문 취소 기능에서 위험한 흐름을 먼저 찾아줘.
필요한 테스트 레벨도 같이 정해줘.
```

## 함께 해결하는 흐름

여러 분야가 필요한 문제는 앞 단계 결과를 다음 Master에게 전달한다.

### 새로운 기능

잡스형이 범위를 정하고, 로드형이 구현하며, 루신이 검증한다.

1. 잡스형: 사용자 문제, 범위, 흐름, 완료 조건
2. 로드형: API, 데이터, 처리 흐름, 운영 코드
3. 루신: 위험, 테스트 범위, 실행 결과, 남은 확인 사항

자세한 순서는 [새로운 기능 만들기](../Playbooks/feature-development.md)에서 확인한다.

### 외부 서비스 연동

호페형이 경계를 설계하고, 로드형이 내부 구현을 연결하며, 루신이 실패 흐름을 검증한다.

1. 호페형: 외부 계약, 상태 모델, 실패와 재처리
2. 로드형: 프로젝트 구조에 맞는 구현
3. 루신: 중복 요청, 타임아웃, 재시도, 회귀 검증

자세한 순서는 [구조 전환하기](../Playbooks/architecture-transition.md)에서 확인한다.

### 조회 성능 개선

대부님이 DB 병목을 찾고, 로드형이 애플리케이션 변경을 반영하며, 루신이 결과를 검증한다.
