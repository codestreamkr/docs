# 04. [중급] 프로젝트 시작

Pi 1.x 공식 문서 기준으로 프로젝트의 기준 상태를 확인하고 첫 작업을 준비해요.  
설치와 인증은 [환경 설정](../setup.md)을 완료하세요.

## 1. 작업 위치와 기존 변경 확인

터미널에서 프로젝트를 열고 Git 상태를 확인하세요.

```bash
cd /path/to/project
git status --short --branch
pi
```

기존 변경 파일은 이후 Pi가 만든 변경과 구분하세요.  
Git 저장소가 아니면 작업 전 백업을 남기세요.

## 2. 프로젝트 구조와 테스트 파악

채팅창에서 실행·테스트 명령을 근거와 함께 요청하세요.

```text
프로젝트 구조와 빌드·테스트 명령을 찾아줘.
README, 빌드 설정과 CI 파일을 근거로 제시해줘.
파일은 수정하지 마.
```

확인한 테스트를 변경 전에 실행하고 기존 실패를 기록하세요.

## 3. 프로젝트 기준 정하기

프로젝트의 반복 기준은 `AGENTS.md`에 적으세요.  
[지침 예제](../setup.md#프로젝트-지침)를 바탕으로 실제 명령을 반영하세요.

```text
확인한 실행·테스트 명령과 작업 기준으로 AGENTS.md 초안을 보여줘.
아직 파일은 저장하지 마.
```

초안을 확인한 뒤 저장을 요청하세요.

## 4. 필요한 자원만 추가

| 필요한 것 | 위치 또는 문서 |
| --- | --- |
| 프로젝트 설정 | `.pi/settings.json` |
| 반복 요청 | `.pi/prompts/` |
| 작업 절차 | `.pi/skills/` 또는 `.agents/skills/` |
| 실행 도구·이벤트 | `.pi/extensions/` |
| 공통 도구 묶음 | [예제 Package](../examples/basic-pi-package/) |

프로젝트 자원을 확인한 뒤 `/trust`로 결정하고 Pi를 다시 실행하세요.  
기본 기능으로 충분하면 별도 Extension을 만들 필요가 없어요.

## 5. 작은 작업으로 확인

```text
README의 실행 명령이 실제 빌드 설정과 일치하는지 확인해줘.
불일치한 부분만 수정하고 근거와 검증 결과를 알려줘.
```

기존 Git 상태와 변경 후 파일을 대조하세요.  
현재 파일과 테스트 결과가 요청 범위에 맞으면 다음 작업을 진행하세요.
