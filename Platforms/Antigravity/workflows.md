# Antigravity 작업 흐름

여러 결과가 필요한 작업에서는 앞 단계의 확정된 결과를 다음 Skill의 입력으로 연결해요.

문제 유형별 흐름과 단계별 판단 기준은 [Playbook](../../Playbooks/README.md)에서 관리해요.  
이 문서는 Antigravity에서의 호출, 특화 슬래시 명령 연계와 아티팩트 기반 작업 흐름을 다뤄요.

## 호출과 연결

Skill 이름 앞에 `/`를 붙이고, 앞 단계가 만든 결과를 다음 호출에서 지정해요.

```text
/ct-plan-work 주문 취소의 중복 요청 방지 기능 구현 계획을 작성해줘
        ↓
/ct-code-spring 확정된 계획을 기준으로 구현하고 관련 테스트를 실행해줘
        ↓
/ct-qa-flow 주문 취소의 정상·중복·외부 실패 흐름을 검증해줘
```

다음 Skill을 호출할 때 앞 단계의 결과 중 필요한 항목을 지정해요.

- 확정된 범위와 제외 범위
- 변경 대상과 유지할 계약
- 근거 문서 또는 코드 경로
- 검증 기준과 미확인 사항

대화만으로 대상을 구분하기 어렵다면 앞 단계가 만든 문서나 파일 경로를 함께 전달해요.

## Antigravity 고유 작업 방식: 아티팩트(Artifacts)와 피드백

Antigravity는 긴 호흡의 작업 결과를 터미널 스크롤 텍스트로 흘려보내지 않고 아티팩트로 관리해요.

1. **계획 및 설계의 아티팩트화**:
   - `/plan`이나 `ct-plan-work`를 호출하면 구조화된 Markdown 아티팩트가 생성돼요.
   - 아키텍처 다이어그램은 Mermaid 구문으로 시각화되어 아티팩트 내에 바로 렌더링돼요.
2. **코드 변경과 인라인 검토**:
   - 코드를 수정하기 전 계획 검토 버튼이나 `/diff` 명령으로 변경 예정 내용을 미리 확인해요.
   - `/diff` 화면에서 `c`를 누르면 변경 특정 줄에 인라인 코멘트를 달아 에이전트에게 즉시 재수정을 요구할 수 있어요.
3. **독립된 맥락 유지**:
   - 아티팩트는 세션이 길어져도 휘발되지 않고 유지되므로, 다음 단계 Skill을 호출할 때 확정된 정본 문서로 활용할 수 있어요.

## 긴 작업의 맥락 관리

단계가 이어지면 현재 세션에 남은 맥락을 관리해요.

- `agy -c`: 이전 세션의 대화와 맥락을 이어서 계속 진행해요.
- `agy --conversation <id>`: 특정 작업 ID의 세션으로 바로 복귀해요.
- `/clear`: 앞 단계와 무관한 새 작업을 시작할 때 대화 컨텍스트를 비워요.
- `/plan`: 여러 단계가 얽힌 작업 전 단계별 실행 계획을 먼저 수립해요.

단계 사이에 맥락을 정리한 경우 다음 Skill 호출에 필요한 결과 문서와 경로를 다시 지정해요.
