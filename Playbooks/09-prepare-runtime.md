# 실행 환경 준비하기

빌드, 테스트와 로컬 실행 절차를 실제로 동작하는 형태로 고정한다.

## 흐름

```text
ct-script-run    스크립트, 필요한 환경변수 이름, 실행 방법과 검증 결과
      ↓
ct-plan impl     정본 문서로 정리할 항목                   ← 문서 기준까지 정할 때
```

## 단계별로 확정할 것

### 시작 전 조사

스크립트를 만들기 전에 실제 파일과 명령을 확인한다.

- 빌드 파일과 패키지 관리자
- 소스와 테스트 디렉터리
- 애플리케이션 진입점
- CI 설정과 기존 실행 스크립트
- 필요한 외부 의존 서비스

### ct-script-run

- 대상 운영체제
- 의존성 설치, 빌드, 테스트, 실행 각각의 명령
- 필요한 환경변수의 이름과 용도
- 실행하지 못한 명령과 그 이유

비밀값은 스크립트 본문에 넣지 않고 환경변수 이름만 남긴다. 확인하지 못한 명령은 동작한다고 적지 않는다.

### ct-plan impl

프로젝트 문서의 책임을 나눈다.

| 문서 | 책임 |
| --- | --- |
| 프로젝트 구조 | 기술 스택, 모듈, 진입점, 아키텍처 경계 |
| 코드 스타일 | 네이밍, 계층별 작성 기준, 로깅과 오류 처리 |
| 작업 절차 | 빌드, 테스트, 실행, 환경변수와 배포 확인 |

같은 규칙을 여러 문서에서 반복하지 않는다. 지침 파일에는 항상 지킬 짧은 규칙과 정본 문서 링크만 둔다.

## 다음 단계로 넘길 것

- 검증된 실행 명령
- 필요한 환경변수와 외부 의존 서비스
- 정본 문서의 위치
- 실행하지 못한 명령과 확인 주체

## 이 Playbook을 벗어나는 경우

- 실행은 되는데 코드 구조를 모르면 [03](./03-understand-code.md)을 사용한다.
- 지침 파일의 위치와 로딩 순서는 사용하는 제품의 환경 설정 문서에서 확인한다.
