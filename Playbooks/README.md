# Playbook

Playbook은 문제 유형별로 어떤 결과를 어떤 순서로 만들지 정리한다.

하나의 Skill로 끝나는 작업에는 Playbook이 필요 없다. 앞 단계의 결과가 다음 단계의 입력이 되어야 할 때 사용한다.

Skill의 호출 표기와 제품별 실행 방법은 [플랫폼 문서](#실행)에서 확인한다. Playbook은 호출 표기를 다루지 않는다.

## 공통 진행 규칙

Playbook은 실행 환경이 바뀌어도 같은 결과 기준을 사용한다.

### 시작 전

- 해결하려는 문제와 완료 조건을 한 문장으로 적는다.
- 관찰한 사실과 추정을 구분한다. 추정은 근거를 얻기 전까지 결정에 쓰지 않는다.
- 유지해야 할 계약(API 응답, 데이터, 운영 절차)을 먼저 확정한다.

### 단계 사이

- 필요하지 않은 단계는 사용하지 않는다. 흐름은 순서지 의무가 아니다.
- 앞 단계의 결과가 확정되기 전에 다음 단계를 시작하지 않는다.
- 중간에 전제가 바뀌면 이어서 진행하지 말고 해당 단계로 돌아간다.

### 결과 전달

다음 단계를 시작할 때 앞 단계의 결과 중 필요한 항목을 지정한다.

- 확정된 범위와 제외한 범위
- 변경 대상과 유지할 계약
- 근거 문서 또는 코드 경로
- 검증 기준과 아직 확인하지 못한 사항

대화만으로 대상을 구분하기 어렵다면 앞 단계가 만든 문서나 파일 경로를 함께 전달한다.

### 마무리

- 실제 변경과 검증 결과를 나눠서 기록한다.
- 실행하지 못한 검증과 남은 위험을 남긴다.
- 미확정 정책은 결정 주체와 함께 적는다.
