# Codex 작업 흐름

열린 세션에서 Skill을 연결하고 변경 검토, 세션 관리와 병렬 조사를 진행해요.  
공통 작업 절차와 단계별 판단 기준은 [Playbook](../../Playbooks/README.md)을 봐요.

## 호출과 연결

입력창에서 `$ct-*`를 호출하고, 앞 단계의 확정된 결과를 다음 요청에 지정해요.

```text
$ct-plan 주문 취소의 중복 요청 방지 계획을 .docs/order-cancel-plan.md에 작성해줘
        ↓
$ct-apply .docs/order-cancel-plan.md의 남은 작업을 구현·검증하고 완료 상태를 기록해줘
        ↓
$ct-verify 주문 취소 변경의 정상·중복·외부 실패 흐름이 계획의 완료 조건을 충족하는지 검증해줘
```

다음 단계에는 [Playbook 공통 기준](../../Playbooks/README.md#공통-기준)에 따라 확정된 결과와 근거 파일 경로를 전달해요.  
각 Skill의 입력과 결과는 [사용자 Skill](./skills.md)에서 확인해요.

## 변경 확인과 검토

커밋 전 변경 파일과 구현의 문제를 확인해요.

1. 입력창에서 `/diff`를 열어 요청 밖 변경과 누락된 파일을 확인해요.
2. `/review`를 열고 현재 변경이나 기준 브랜치 등 필요한 검토 대상을 선택해요.
3. 지적 사항의 근거를 확인하고 수정·재검증을 요청해요.

```text
검토에서 지적한 중복 취소와 트랜잭션 문제를 현재 코드에서 확인해줘.
재현되는 문제를 수정하고 관련 회귀 테스트를 실행해줘.
변경 파일, 실행 결과와 해결하지 못한 항목을 알려줘.
```

- 지적 사항별 수정 여부, 변경 diff, 테스트 결과와 미검증 범위를 확인해요.
- 검토 응답만으로 수정과 테스트까지 완료된 것으로 보지 않아요.
- Spring 구현 관례는 현재 코드와 설정을 근거로 검토해요.
- 스크립트에서 검토 결과를 받을 때는 [비대화형 검토 명령](./commands.md#터미널에서-실행)을 사용해요.

## 실행 중 방향 전환하기

CLI `0.159.0`부터 `instant_interrupt`를 켜면 모델 응답이나 긴 Code Mode 호출 중 새 입력으로 방향을 바꿀 수 있어요.

```bash
codex --enable instant_interrupt
```

1. 요청을 시작하고 변경할 조건이 생기면 입력창에 새 지시를 보내세요.
2. Codex가 새 지시를 반영했는지 다음 응답과 변경 파일에서 확인하세요.

```text
구현을 멈추고 현재까지 확인한 원인과 남은 검증만 보고해줘.
```

이 기능은 선택해서 켜는 기능이에요.  
이미 실행한 명령이나 파일 변경을 되돌리지 않아요.  
지원 버전은 [공식 릴리스](https://learn.chatgpt.com/docs/changelog#september-2026)를 확인하세요.

## 대화 블록 복사하기

CLI `0.162.0`부터 `/copy`로 대화 기록의 블록을 탐색하고 복사할 수 있어요.

1. 입력창에서 `/copy`를 실행하고 필요한 블록을 선택하세요.
2. 일부 텍스트만 필요하면 선택한 뒤 `Ctrl+Insert`를 누르세요.
3. 붙여넣은 내용에서 코드와 표의 형식을 확인하세요.

버전별 동작은 [공식 릴리스](https://learn.chatgpt.com/docs/changelog#october-2026)를 확인하세요.

## GitLab Merge Request 검토하기

Codex Cloud에서 GitLab Merge Request를 검토할 때 사용해요.  
GitLab 연동은 베타 기능이에요.

1. GitLab 계정을 연결하고 Codex Cloud에 대상 프로젝트 환경을 만드세요.
2. 환경의 **Enable Codex activity from GitLab**을 켜서 웹훅을 연결하세요.
3. 저장소의 `AGENTS.md`에 프로젝트 고유 리뷰 규칙을 작성하세요.
4. Merge Request 댓글에서 검토를 요청하세요.

```text
@codex review for issues in the database migration
```

5. 지적 사항을 코드와 테스트로 확인하세요.
6. 수정 작업을 요청한 뒤 변경 diff와 CI 결과를 검토하세요.

```text
@codex fix the P1 issue
```

- 자동 리뷰는 Codex 리뷰 설정의 **Automatic reviews**에서 저장소와 실행 조건을 선택하세요.
- Self-Managed·Dedicated는 관리자 연결 설정이 필요해요. 서명된 웹훅은 GitLab 19.0 이상을 요구해요.
- 웹훅 생성 권한과 Codex가 리뷰를 게시할 프로젝트 접근 권한을 확인하세요.
- 그룹 웹훅만 설정하면 리뷰를 할 수 있어요. 코드 수정·명령 실행에는 프로젝트 환경이 필요해요.
- GitLab이 접거나 생략한 대규모 diff는 검토를 완료할 수 없어요.
- 리뷰 결과는 테스트와 병합 승인을 대신하지 않아요.

상세 연결과 자동 리뷰 조건은 [GitLab 공식 안내](https://learn.chatgpt.com/docs/third-party/gitlab)를 확인하세요.

## 대화 결과 공유하기

macOS 데스크톱 앱에서 로컬 Codex 대화를 읽기 전용 스냅샷으로 공유해요.

1. 공유할 대화의 **Share**를 선택하세요.
2. 조직 계정에서는 **Who has access**로 공개 대상을 선택하세요.
3. 업로드가 끝나면 **Copy link**를 선택하세요.
4. 복사한 링크를 열어 메시지·이미지·파일 경로·diff를 확인하세요.

- 개인 계정의 링크는 링크를 가진 사람이 열 수 있어요.
- 조직 계정은 원래 워크스페이스의 인증된 구성원으로 접근을 제한해요.
- 스냅샷은 공유 시점의 내용만 포함해요. 이후 대화와 변경은 반영하지 않아요.
- 자동 비밀값 제거 후에도 민감한 내용이 남을 수 있어요. 공유 화면을 직접 확인하세요.
- 링크를 폐기하려면 ChatGPT 데이터 설정의 **Shared links**를 사용하세요.

공유 범위와 포함 항목은 [공식 스냅샷 안내](https://learn.chatgpt.com/docs/use-chatgpt#share-a-read-only-snapshot-of-a-codex-thread)를 확인하세요.

## 모바일에서 Worktree 작업하기

iOS의 Codex Remote에서 연결한 컴퓨터의 Worktree 작업을 시작하고 검토해요.

1. 모바일 앱과 연결할 컴퓨터의 데스크톱 앱을 업데이트하세요.
2. 새 작업에서 컴퓨터와 프로젝트를 선택하세요.
3. Worktree의 시작 브랜치를 선택하거나 현재 로컬 변경 포함을 선택하세요.
4. 설정 완료 후 작업을 열고 경로·브랜치·미커밋 변경을 확인하세요.
5. 변경과 테스트 결과를 검토하세요.

- iOS 26에서는 Worktree 설정을 백그라운드에서 계속하고 Live Activity로 진행을 확인할 수 있어요.
- `@`로 다른 작업을 참조할 수 있어요.
- 모바일 diff가 데스크톱의 같은 Worktree를 가리키는지 확인하세요.
- 통합과 정리는 [Worktree 변경 비교·통합·정리](#변경-비교와-통합)를 따라요.

지원 범위는 [공식 릴리스 기록](https://learn.chatgpt.com/docs/changelog)을 확인하세요.

## 앱 화면을 문맥으로 전달하기

Appshot으로 오류 창이나 미리보기 화면을 Codex에 전달해요.  
데스크톱 앱의 macOS·Windows에서 사용할 수 있어요.

1. 앱 설정의 **Appshot destination**을 **Current chat**으로 선택하세요.
2. 전달할 창을 화면 맨 앞으로 가져오세요.
3. Windows에서는 양쪽 Alt 키를, macOS에서는 양쪽 Command 키를 함께 누르세요.
4. 첨부한 화면과 요청할 분석 범위를 확인하세요.

```text
첨부한 브라우저 오류 화면을 현재 프로젝트 코드와 대조해줘.
오류 원인과 재현 절차를 정리해줘. 파일은 수정하지 마.
```

- Appshot은 창 이미지와 앱이 제공하는 텍스트를 포함할 수 있어요.
- 전체 문서나 화면 밖 텍스트를 항상 포함하지는 않아요.
- CLI에서는 새 Appshot을 만들 수 없어요.

단축키와 권한 설정은 [Appshots 공식 안내](https://learn.chatgpt.com/docs/appshots)를 확인하세요.

## 세션과 맥락 관리

CLI 입력창에서 현재 대화를 관리해요.

| 상황 | 방법 | 다음 요청에 전달할 것 |
| --- | --- | --- |
| 현재 상태를 확인해요 | `/status` | 작업 루트와 현재 설정 |
| 긴 대화의 맥락을 줄여요 | `/compact` | 확정 결과, 계획 경로와 남은 작업 |
| 중단한 작업을 이어가요 | `/resume` | 이전 결과와 현재 코드의 차이 |
| 같은 요구사항으로 다른 접근을 비교해요 | `/fork` | 유지할 요구사항과 비교할 대안 |
| 별개의 작업을 시작해요 | `/new` | 새 작업의 대상과 완료 조건 |

재개한 세션에서는 먼저 이전 결과와 현재 파일 상태를 대조해요.

```text
이전 작업의 완료·미완료 항목을 정리하고 현재 Git 상태와 대조해줘.
다른 변경과 충돌하지 않는지 확인한 뒤 남은 구현과 관련 테스트를 진행해줘.
```

분기한 세션에서는 유지할 조건과 변경할 접근을 지정해요.

```text
기존 대화의 요구사항은 유지하고, 캐시를 추가하지 않는 대안을 비교해줘.
코드는 수정하지 말고 변경 범위와 검증 방법을 알려줘.
```

`/fork`는 대화 이력을 나누며 파일을 격리하지 않아요.  
같은 디렉터리의 두 세션에서 같은 파일을 동시에 수정하지 않도록 해요.  
CLI를 종료한 상태라면 [터미널의 재개·분기 명령](./commands.md#터미널에서-실행)으로 시작할 수 있어요.

## Codex 고유 작업

### 별도 작업 공간에서 구현하기

현재 체크아웃과 파일을 분리해야 할 때 Git Worktree를 사용해요.

#### 작업 공간 준비

- 앱에서는 새 대화의 **Worktree**와 시작 브랜치를 선택해요.
- CLI에서 새 Worktree 세션을 만들 때는 터미널에서 다음 명령을 실행해요.

```bash
codex --worktree
```

CLI `0.162.0`부터 신뢰한 로컬 프로젝트에서 관리 Worktree 생성·조회 도구도 사용할 수 있어요.  
Worktree 기능을 켠 환경에서만 제공해요.  
도구가 제공되면 대상 저장소와 시작 지점을 명시해 생성이나 목록 조회를 요청하세요.

작업 공간이 열린 뒤 입력창에서 위치와 계획 파일을 확인하고 구현을 요청해요.

```text
현재 Worktree 경로, HEAD와 브랜치, 미커밋 변경을 먼저 확인해줘.
.docs/order-cancel-plan.md가 이 작업 공간에 있는지 확인하고,
그 계획의 중복 취소 방지 범위만 구현한 뒤 관련 테스트를 실행해줘.
```

- 미커밋 계획 파일은 새 공간에도 있는지 확인하고 전달해요.
- 의존성, 환경변수와 무시된 파일은 별도 준비가 필요할 수 있어요.
- 앱의 준비 절차는 [Local environments](https://learn.chatgpt.com/docs/environments/local-environment)를 봐요.

#### 변경 비교와 통합

1. Worktree에서 `/diff`와 테스트 결과를 확인해요.
2. 앱에서 detached HEAD의 변경을 브랜치에 보존하려면 **Create branch here**를 사용해요.
3. 커밋·PR·병합은 프로젝트 절차에 따라 대상과 범위를 명시해 요청해요.
4. 앱의 대화와 코드를 로컬 체크아웃으로 옮겨 계속하려면 **Handoff**를 사용해요.
5. 보존·통합 여부와 미커밋 파일을 확인한 뒤 작업 공간을 정리해요.

```text
현재 Worktree 변경의 보존 여부와 대상 브랜치에 통합됐는지 확인해줘.
미커밋 파일과 남은 검증을 보고하고, 정리 가능한 작업 공간을 알려줘.
```

Git 브랜치 생성·비교·정리를 직접 수행할 때는 별도 터미널에서 [Worktree 가이드](../../Git/git_01_worktree_guide.md)를 따라요.  
같은 브랜치를 두 Worktree에서 동시에 체크아웃할 수 없어요.  
Handoff는 작업 위치를 옮기는 절차이며, 대상 브랜치에 병합됐는지는 별도로 확인해요.

### 큰 코드베이스 병렬 조사하기

서로 독립된 모듈은 Subagent에 분담 범위와 결과 형식을 지정해 조사해요.

```text
주문 취소 흐름을 Subagent로 병렬 조사해줘.
한 에이전트는 주문 상태 전이, 다른 에이전트는 결제 취소 연동을 읽기 전용으로 분석해줘.
각자 진입점, 관련 파일·심볼, 실패 조건과 기존 테스트를 보고해줘.
모든 결과를 받은 뒤 호출 순서와 확인되지 않은 부분을 하나로 정리해줘.
```

- CLI에서는 `/agent`로 작업 상태를 확인하거나 Subagent 대화로 전환해요.
- CLI `0.162.0`부터 지원 서버의 Command Center에서 `p`를 눌러 작업을 Pinned 그룹에 고정할 수 있어요.
- 이전 작업은 **Show more**로 조회해요. CLI `0.160.0`부터 지원해요.
- 메인 세션에서 모듈별 근거와 상충하는 설명을 대조하고 구현 범위를 확정해요.
- 구현을 분담할 때는 담당 파일이 겹치지 않게 지정해요.
- Subagent의 컨텍스트 분리를 파일 작업 공간의 격리로 가정하지 않아요.
- 반복 역할의 설정은 [Subagent 안내](./extensions.md#subagent)를 봐요.

### 연결된 도구로 런타임 확인하기

IntelliJ IDEA MCP로 실제 실행 상태를 확인할 때는 사용할 도구와 대상 세션을 지정해요.

1. 입력창의 `/mcp`에서 연결·인증·노출 도구를 확인해요.
2. [IntelliJ 런타임 디버깅](../../IntelliJ/intellij_01_runtime_debug_guide.md)에 따라 디버그 세션을 준비해요.
3. 중단된 위치와 확인할 값을 요청해요.

```text

```
