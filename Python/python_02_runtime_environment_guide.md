# 실행 환경과 가상환경

이 문서는 프로젝트가 요구하는 Python 버전을 고정하고 의존성을 격리하는 방법을 안내한다.

Python은 시스템 전역에 패키지를 설치할 수 있어서 프로젝트 간 충돌이 쉽게 발생한다. 모든 작업은 프로젝트 전용 환경 안에서 실행한다.

## 기본 원칙

환경 문제의 대부분은 다음 세 가지로 해결된다.

- 프로젝트마다 가상환경을 하나 만든다.
- 인터프리터 버전은 파일로 명시하고 사람이 기억하지 않는다.
- 실행 명령은 활성화된 환경 안에서만 사용한다.

## 인터프리터 버전 관리

시스템 Python은 OS가 사용하므로 프로젝트 실행에 쓰지 않는다.

| 도구 | 용도 | 선택 기준 |
| --- | --- | --- |
| uv | 인터프리터 설치와 가상환경, 의존성 관리를 함께 처리 | 새 프로젝트 기본 선택 |
| pyenv | 인터프리터 버전만 설치·전환 | 의존성 도구를 따로 쓰는 기존 프로젝트 |
| 배포판 패키지 관리자 | OS 기본 Python 제공 | 시스템 도구 실행 용도로만 사용 |

버전 고정 파일은 저장소에 커밋한다.

- `.python-version`: 사용할 인터프리터 버전을 한 줄로 적는다. uv와 pyenv가 함께 인식한다.
- `pyproject.toml`의 `requires-python`: 프로젝트가 지원하는 버전 범위를 선언한다.

```toml
[project]
requires-python = ">=3.13"
```

## 가상환경 만들기

가상환경은 프로젝트 루트의 `.venv/`에 만든다.

```bash
# uv 사용
uv venv                       # .python-version 기준으로 생성
uv venv --python 3.13         # 버전 직접 지정

# 표준 라이브러리 사용
python3.13 -m venv .venv
```

활성화와 해제는 다음과 같다.

```bash
source .venv/bin/activate     # macOS, Linux
.venv\Scripts\activate        # Windows
deactivate
```

`.venv/`는 `.gitignore`에 추가하고 커밋하지 않는다.

## 활성화 없이 실행하기

uv를 쓰면 활성화 단계를 생략할 수 있다. CI와 스크립트에서는 이 방식을 사용한다.

```bash
uv run python -m app          # 프로젝트 환경에서 실행
uv run pytest
```

## 현재 환경 확인

명령이 예상과 다르게 동작하면 실행 주체부터 확인한다.

```bash
which python                  # 활성 환경의 인터프리터인지 확인
python -c "import sys; print(sys.executable)"
python -m pip --version       # pip가 어느 환경에 연결됐는지 확인
```

- `python`과 `pip`가 서로 다른 환경을 가리키면 `python -m pip` 형태로 실행한다.
- 설치했는데 `ModuleNotFoundError`가 나면 설치 대상 환경과 실행 환경이 다른 경우다.

## 환경 변수와 설정 값

애플리케이션 설정은 코드에 두지 않고 환경 변수로 주입한다.

- 로컬 개발: `.env` 파일에 두고 `.gitignore`에 추가한다.
- 예시 파일: `.env.example`에 키 이름과 설명만 남겨 커밋한다.
- 운영 환경: 배포 플랫폼의 비밀 관리 기능을 사용한다.
- 로딩 방식: 프레임워크 설정 객체에서 한 번만 읽고, 코드 곳곳에서 `os.environ`을 직접 참조하지 않는다.

설정 값 구조는 [웹 백엔드 구조 선택](./python_05_web_backend_structure_guide.md)에서 다룬다.

## 자주 발생하는 문제

| 증상 | 원인 | 조치 |
| --- | --- | --- |
| 설치한 패키지를 못 찾는다 | 가상환경 밖에서 실행 | 활성화 후 재실행하거나 `uv run` 사용 |
| 전역 설치가 권한 오류로 막힌다 | 시스템 환경에 설치 시도 | 가상환경을 만들고 그 안에서 설치 |
| 팀원과 동작이 다르다 | 인터프리터 마이너 버전 차이 | `.python-version` 기준으로 재생성 |
| 설치 중 컴파일 오류가 난다 | 해당 플랫폼 wheel 없음 | 패키지 버전 변경 또는 빌드 도구 설치 |
| 환경이 꼬여 원인을 못 찾는다 | 누적된 수동 설치 | `.venv/` 삭제 후 lock 파일로 재생성 |

환경을 초기화할 때는 다음 순서를 사용한다.

```bash
rm -rf .venv
uv sync
```
