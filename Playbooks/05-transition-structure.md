# 구조 전환하기

기존 동작을 유지하면서 구조를 단계적으로 옮기고 제거 조건까지 정해요.

## 흐름

```text
ct-code-tree         현재 호출·상태 변경·외부 경계 확인
      ↓
ct-plan-work         목표 책임, 이동 순서와 롤백 조건 확정
      ↓
ct-code-tree-test    전환 전후의 동작을 비교할 테스트
      ↓
ct-code-spring       검증 가능한 단계별 구현  ← 코드 반영이 필요할 때
```

## 다음 단계로 넘어갈 기준

- 현재 API·상태·운영 재처리 경로와 노출된 계약을 확인해요.
- 구성요소별 유지·이동·폐기 방식을 정하고 각 단계를 독립적으로 검증하고 되돌릴 수 있게 해요.
- 제한된 대상부터 새 경로를 적용하고 기존 경로와 결과·상태를 비교해요.
- 병행 운영의 성공·롤백 조건을 충족한 뒤 적용 대상을 넓혀요.
- 기존 구조는 제거 조건을 확인한 뒤에만 없애요.
