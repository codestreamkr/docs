# 작업 방식 자동화하기

반복되는 문제 해결 방식은 공통 기준을 먼저 정하고 플랫폼별 Skill·Agent로 구현한다.

## 자동화할 대상을 고르기

반복성과 결과 형식이 분명한 작업부터 선택한다.

- 같은 입력을 반복해서 수집한다.
- 작업 순서와 완료 조건이 안정적이다.
- 결과 문서나 코드 형태가 정해져 있다.
- 사람이 매번 기억하기 어려운 검증 항목이 있다.

## 1. 공통 계약 정의

플랫폼 구현 전에 작업의 정본을 만든다.

- 목적과 사용하는 경우
- 필요한 입력
- 작업 순서
- 결과 형식
- 완료 조건
- 필요한 도구와 외부 데이터

Master의 역할은 `Masters`, 여러 역할의 연결은 `Playbooks`에 기록한다.

## 2. 실행 방식 선택

자동화 성격에 맞는 구성요소를 고른다.

| 필요한 것 | 실행 방식 |
| --- | --- |
| 반복 절차와 전문 지식 | Skill |
| 사용자가 직접 시작하는 고정 흐름 | Command |
| 역할이 고정된 독립 작업 | Agent |
| 최신 외부 데이터와 도구 | MCP 또는 Connector |
| 항상 실행할 결정적 검사 | Hook |
| 여러 구성요소의 배포 | Plugin 또는 패키지 |

명칭과 지원 범위는 플랫폼마다 다르다.

## 3. 플랫폼별 구현

공통 계약을 각 플랫폼 형식으로 연결한다.

- Codex: Skill, `AGENTS.md`, MCP, Subagent, Hook과 Plugin
- Claude Code: Skill, Command, Custom Agent, `CLAUDE.md`, MCP와 Hook

플랫폼 구현에는 호출명, 파일 위치, 허용 도구와 상태 확인 방법만 추가한다.

## 4. 동등성 확인

Codex와 Claude Code의 결과가 같은 공통 기준을 충족하는지 확인한다.

- 같은 상황에서 같은 Master가 선택된다.
- 필수 입력이 같다.
- 결과의 필수 섹션이 같다.
- 완료 조건과 검증 기준이 같다.
- 플랫폼 차이는 호출과 도구 사용에만 남는다.

## 5. 변경 관리

공통 계약과 플랫폼 구현의 변경 책임을 나눈다.

- 역할과 결과 변경: Master 문서부터 수정
- 작업 순서 변경: Playbook부터 수정
- 호출 문법과 파일 위치 변경: 해당 플랫폼 문서와 구현 수정
- 신규 플랫폼 추가: 공통 문서를 복사하지 않고 연결 문서 추가

## 완료 기준

자동화는 플랫폼이 바뀌어도 같은 결과를 만들어야 한다.

- 공통 역할과 작업 순서의 정본이 있다.
- Codex와 Claude Code 구현 위치가 분리되어 있다.
- 현재 적용 상태를 플랫폼별로 확인할 수 있다.
- 한 플랫폼의 명령이 공통 문서에 섞이지 않는다.
- 변경해야 할 정본을 한 곳에서 찾을 수 있다.
