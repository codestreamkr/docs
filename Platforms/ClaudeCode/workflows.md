# Claude Code 작업 흐름

여러 결과가 필요한 작업에서는 앞 단계의 확정된 결과를 다음 Skill의 입력으로 연결해요.  
문제 유형별 흐름과 판단 기준은 [Playbook](../../Playbooks/README.md)에서 관리하고, 이 문서는 Claude Code에서의 호출과 연결 방법만 다뤄요.

## 호출과 연결

Skill 이름 앞에 `/`를 붙이고, 앞 단계가 만든 결과를 다음 호출에서 지정해요.

```text
/ct-plan-work 주문 취소의 중복 요청 방지 기능 구현 계획을 작성해줘
        ↓
/ct-code-spring 확정된 계획을 기준으로 구현하고 관련 테스트를 실행해줘
        ↓
/ct-qa-flow 주문 취소의 정상·중복·외부 실패 흐름을 검증해줘
```

다음 Skill을 호출할 때 앞 단계의 결과 중 필요한 항목을 지정해요.

- 확정된 범위와 제외 범위
- 변경 대상과 유지할 계약
- 근거 문서 또는 코드 경로
- 검증 기준과 미확인 사항

대화만으로 대상을 구분하기 어렵다면 앞 단계가 만든 문서나 파일 경로를 함께 전달해요.

## 긴 작업의 맥락 관리

단계가 이어지면 현재 세션에 남은 맥락을 확인해요.

- `/context`: 현재 컨텍스트 사용량과 적용된 지침 파일 확인
- `/compact`: 확정된 결과만 남기고 대화 요약
- `/clear`: 앞 단계와 무관한 새 작업 시작
- `/rewind`: 잘못 반영된 변경을 이전 지점으로 되돌리기
- `/branch`: 앞 단계는 그대로 두고 다른 방향을 시도

단계 사이에 맥락을 정리한 경우 다음 Skill 호출에 필요한 결과 문서와 경로를 다시 지정해요.

## 나눠서 진행하기

앞 단계의 결과가 필요 없는 작업은 현재 세션 밖에서 돌려요.

| 상황 | 방법 |
| --- | --- |
| 현재 체크아웃을 두고 다른 브랜치에서 작업해야 해요 | `claude -w`로 별도 worktree 세션 |
| 오래 걸리는 검증을 돌려두고 싶어요 | `claude --bg` 또는 `/background` |
| 독립된 조사나 검토만 떼고 싶어요 | Subagent에 위임하고 `/tasks`로 확인 |

무엇을 나눌지의 판단 기준은 [Playbook](../../Playbooks/README.md)에서 관리해요.  
나눈 작업의 결과도 다음 Skill 호출에 문서나 경로로 전달해요.
