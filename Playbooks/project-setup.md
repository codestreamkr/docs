# 프로젝트 준비하기

AI가 저장소 안에서 일관되게 작업하려면 구조, 코드 스타일과 실행 절차의 정본을 먼저 정한다.

## 준비 결과

프로젝트 문서는 세 가지 책임으로 나눈다.

| 문서 | 책임 |
| --- | --- |
| 프로젝트 구조 | 기술 스택, 모듈, 진입점, 아키텍처 경계 |
| 코드 스타일 | 네이밍, 계층별 작성 기준, 로깅과 오류 처리 |
| 작업 절차 | 빌드, 테스트, 실행, 환경 변수와 배포 확인 |

플랫폼 지침 파일은 이 문서를 찾는 라우팅과 필수 행동 기준만 담는다.

## 1. 저장소 조사

실제 파일과 명령을 근거로 초안을 만든다.

- 빌드 파일과 패키지 관리자
- 소스와 테스트 디렉터리
- 주요 모듈과 애플리케이션 진입점
- CI와 실행 스크립트
- 기존 문서와 지침 파일

## 2. 문서 책임 분리

같은 규칙은 한 문서에서만 관리한다.

- 구조 상세: 프로젝트 구조 문서
- 코드 작성 상세: 코드 스타일 문서
- 명령과 환경 상세: 작업 절차 문서
- 항상 지킬 짧은 규칙과 문서 링크: 플랫폼 지침 파일

## 3. 실행 기준 확인

문서에 적은 명령이 실제로 동작하는지 확인한다.

- 의존성 설치
- 빌드 또는 컴파일
- 단위 테스트
- 로컬 실행
- 필요한 외부 의존 서비스

실행하지 못한 명령은 필요한 환경과 확인 주체를 함께 적는다.

## 4. 플랫폼 연결

공통 문서를 각 플랫폼의 지침 파일에서 참조한다.

- Codex: `AGENTS.md`와 `.codex/config.toml`
- Claude Code: `CLAUDE.md`와 `.claude/settings*.json`

파일의 생성과 동기화 방법은 플랫폼 문서에서 확인한다.

## 완료 기준

새 세션에서도 같은 작업 기준을 찾을 수 있어야 한다.

- 프로젝트 구조, 스타일과 실행 절차의 정본이 분리되어 있다.
- 플랫폼 지침 파일이 정본 문서를 참조한다.
- 같은 상세 규칙이 여러 문서에 반복되지 않는다.
- 빌드와 테스트 명령의 실행 여부를 확인했다.
- 프로젝트 변경 시 갱신할 문서가 분명하다.
