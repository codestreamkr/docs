# 로드형의 Spring MyBatis

MyBatis 문서는 Mapper, XML, 동적 SQL과 결과 매핑이 중심인 작업에 사용한다.

## 사용하는 경우

입력 계약, SQL과 결과 객체의 연결을 정리한다.

- Mapper 인터페이스와 XML의 책임을 나눈다.
- 검색 조건과 동적 SQL을 정리한다.
- alias, `resultMap`과 DTO 매핑을 설계한다.
- 목록과 count 쿼리의 조건을 일치시킨다.
- 페이징과 허용된 정렬 컬럼을 구성한다.
- 기존 MyBatis 구조를 프로젝트 스타일에 맞게 개선한다.

## 필요한 입력

Mapper와 조회 계약을 함께 전달한다.

- Mapper 인터페이스와 XML 위치
- 입력 객체와 결과 DTO
- 현재 SQL과 발생한 결과 문제
- 검색, 정렬과 페이징 요구사항
- 목록·count의 일관성 기준
- 사용하는 DB와 MyBatis 버전

## 진행 기준

로드형은 XML을 바꾸기 전에 입력과 출력 계약을 확인한다.

1. Mapper 구조와 SQL 스타일을 읽는다.
2. 입력 객체와 결과 매핑을 확인한다.
3. 동적 조건과 공통 SQL의 책임을 나눈다.
4. 목록, count와 정렬 기준을 맞춘다.
5. 실제 SQL과 결과 매핑을 검증한다.

## 결과

유지보수 가능한 Mapper 구조를 남긴다.

- Mapper, XML과 DTO 책임
- 동적 SQL과 검색 조건 구조
- alias 또는 `resultMap` 선택
- 목록·count와 페이징 기준
- 정렬 허용 목록
- SQL 실행과 결과 매핑 검증 항목

## 요청 예시

```text
로드형, 주문 검색 Mapper를 정리해줘.
조건이 늘면서 XML이 길어졌고 목록과 count 조건도 어긋나.
기존 패턴을 유지하면서 조건 객체, 동적 SQL과 검증 기준을 맞춰줘.
```

```text
로드형, 관리자 상세 조회 DTO 필드가 일부 비어.
Order, Member, Payment를 함께 조회하고 있어.
alias와 resultMap 중 맞는 방식을 판단해서 매핑을 고쳐줘.
```

## 확인 기준

Mapper 변경은 생성된 SQL과 결과 객체를 함께 확인한다.

- 조건이 늘어나도 입력 구조를 이해할 수 있다.
- 목록과 count가 같은 필터 기준을 사용한다.
- 정렬 값은 허용 목록으로 제한한다.
- 컬럼과 DTO 필드 매핑을 검증했다.
- 실행 계획과 인덱스 판단이 필요하면 [대부님](../godfather/query-tuning.md)에게 연결한다.
