# Python 생태계 지도

이 문서는 Python 프로젝트에서 만나는 구성 요소가 각각 무엇을 담당하는지 정리한다.

Python은 언어 사양, 실행 환경, 패키지 배포 경로가 서로 다른 주체로 나뉘어 있다. 문제가 생겼을 때 어느 계층을 봐야 하는지 먼저 구분한다.

## 생태계 구성 요소

각 요소는 하나의 책임을 담당한다.

| 계층 | 담당 | 확인 위치 |
| --- | --- | --- |
| 언어 사양 | 문법과 표준 동작 정의 | PEP 문서 |
| 인터프리터 | 코드 실행, GC, 스레드 모델 | `python --version`, `sys.implementation` |
| 표준 라이브러리 | 설치 없이 쓰는 기본 모듈 | `python -c "import sysconfig"` |
| 패키지 인덱스 | 외부 라이브러리 배포와 설치 | PyPI, 사내 인덱스 |
| 패키지 관리 도구 | 의존성 해석, 설치, 버전 고정 | `uv`, `pip`, `poetry` |
| 가상환경 | 프로젝트별 의존성 격리 | `.venv/` |
| 애플리케이션 프레임워크 | 웹, 데이터, 배치 등 도메인 기능 | 프로젝트 의존성 목록 |

## 인터프리터

기본 구현은 CPython이며, 대부분의 프로젝트는 CPython을 전제로 한다.

- CPython: 공식 구현. 모든 C 확장 패키지가 기준으로 삼는다.
- PyPy: JIT 기반 대체 구현. 순수 Python 연산 성능이 필요할 때만 검토한다.
- 실행 파일 위치가 여러 개일 수 있으므로 `which python`으로 현재 사용 중인 인터프리터를 먼저 확인한다.

성능 관련 판단은 GIL(Global Interpreter Lock)을 기준으로 나눈다.

- CPU 연산 위주 작업: 스레드로 병렬화되지 않는다. 프로세스 분리 또는 네이티브 확장으로 처리한다.
- I/O 대기 위주 작업: 스레드 또는 async로 동시 처리 효과가 있다.
- 최신 버전에서 GIL 없는 실행 모드가 실험적으로 제공되지만, 운영 프로젝트는 기본 모드를 전제로 설계한다.

## 버전 정책

Python은 연 1회 마이너 버전을 릴리스하고 각 버전을 약 5년간 지원한다.

- 버전 표기: `3.<minor>.<patch>` 형태이며 호환성 판단은 마이너 버전 기준으로 한다.
- 패치 버전 업그레이드: 보안·버그 수정이므로 빠르게 적용한다.
- 마이너 버전 업그레이드: 문법과 표준 라이브러리 변경이 있으므로 의존성 지원 여부를 먼저 확인한다.
- 지원 종료(EOL) 버전: 보안 패치가 없으므로 운영 환경에서 사용하지 않는다.
- 선택 기준: 새 프로젝트는 최신 안정 버전, 운영 프로젝트는 주요 의존성이 모두 지원하는 최신 버전을 사용한다.

## PEP

PEP는 언어와 생태계 표준을 정하는 제안 문서다. 실무에서 자주 참조하는 항목만 알아두면 된다.

| 번호 | 내용 | 실무에서 쓰는 상황 |
| --- | --- | --- |
| PEP 8 | 코드 스타일 | 린터·포매터 기본 규칙의 근거 |
| PEP 20 | 설계 원칙 | 코드 리뷰 기준 표현 |
| PEP 484 | 타입 힌트 | 타입 검사 도입 근거 |
| PEP 517·518 | 빌드 시스템 인터페이스 | `pyproject.toml`의 `[build-system]` |
| PEP 621 | 프로젝트 메타데이터 표준 | `pyproject.toml`의 `[project]` |
| PEP 660 | 편집 가능 설치 | 로컬 개발 설치 동작 |

## 패키지 배포 경로

외부 라이브러리는 PyPI에서 두 가지 형태로 배포된다.

- wheel(`.whl`): 빌드 완료된 배포본. 설치가 빠르고 대부분 이 경로로 설치된다.
- sdist(`.tar.gz`): 소스 배포본. 설치 시점에 빌드하므로 컴파일러와 헤더가 필요하다.
- 설치 실패가 컴파일 오류로 나타나면 해당 플랫폼용 wheel이 없는 경우다. 버전을 낮추거나 빌드 도구를 갖춰야 한다.
- 사내 인덱스를 쓰는 프로젝트는 인덱스 URL과 인증 설정을 환경 변수 또는 도구 설정에 둔다.

## Java·Spring 대응 관계

기존 경험을 매핑하면 구조를 빠르게 파악할 수 있다.

| Java·Spring | Python | 차이점 |
| --- | --- | --- |
| JDK | CPython 인터프리터 | 시스템에 설치된 버전과 프로젝트 버전을 분리해서 관리한다 |
| Maven·Gradle | uv, pip, Poetry | 빌드와 의존성 관리가 도구별로 나뉘어 있다 |
| `pom.xml`·`build.gradle` | `pyproject.toml` | 의존성, 빌드, 도구 설정을 한 파일에 모은다 |
| 로컬 저장소 | 가상환경 | 프로젝트별 디렉터리에 설치본을 격리한다 |
| Maven Central | PyPI | 이름 선점이 자유로우므로 패키지 신뢰성을 직접 확인한다 |
| Checkstyle·SpotBugs | Ruff | 린트와 포맷을 한 도구로 처리한다 |
| 컴파일 타임 타입 검사 | mypy·Pyright | 실행과 분리된 선택적 검사다 |
| JUnit | pytest | 클래스 없이 함수 단위로 작성한다 |
| Spring Boot | FastAPI, Django, Flask | 단일 표준 프레임워크가 없고 선택이 필요하다 |

## 확인 명령

현재 환경 상태는 다음 명령으로 확인한다.

```bash
python --version              # 인터프리터 버전
which -a python python3       # 인터프리터 경로 목록
python -c "import sys; print(sys.prefix)"   # 현재 활성 환경 경로
python -m pip list            # 설치된 패키지 목록
```
