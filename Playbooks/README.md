# 문제 해결 Playbook

Playbook은 Codex와 Claude Code에서 공통으로 사용하는 작업 순서를 정리한다.

Master가 특정 분야의 판단 기준을 제공한다면 Playbook은 여러 단계와 Master를 하나의 결과로 연결한다. 플랫폼별 Skill·Agent 이름과 호출 문법은 각 플랫폼 문서에서 확인한다.

## 현재 하려는 일

작업 목적에 맞는 문서부터 시작한다.

| 하려는 일 | 시작 문서 | 주요 결과 |
| --- | --- | --- |
| 파일을 안전하게 조사하고 수정한다 | [안전한 작업 흐름](./safe-work-cycle.md) | 범위가 통제된 변경과 검증 결과 |
| 프로젝트 작업 기준을 준비한다 | [프로젝트 준비하기](./project-setup.md) | 구조, 스타일, 실행 기준 |
| 어디서부터 풀지 어려운 문제를 정리한다 | [어려운 문제 풀기](./difficult-problem-solving.md) | 문제 분류와 담당 Master |
| 새로운 기능을 만든다 | [새로운 기능 만들기](./feature-development.md) | 기획, 구현, 검증 결과 |
| 큰 개선 작업을 단계적으로 진행한다 | [계획하고 구현하기](./planning-and-implementation.md) | 우선순위, 설계 결정, 코드 변경 |
| 호출 흐름을 분석하고 테스트로 잇는다 | [분석하고 테스트하기](./analysis-and-testing.md) | 호출 구조, 테스트 대상, 검증 결과 |
| 레거시나 외부 연동을 전환한다 | [구조 전환하기](./architecture-transition.md) | 현재·목표 구조와 전환 순서 |
| 반복 작업을 재사용 가능하게 만든다 | [작업 방식 자동화하기](./workflow-automation.md) | 공통 기준과 플랫폼별 자동화 |

## 공통 사용 원칙

Playbook은 실행 환경이 바뀌어도 같은 결과 기준을 사용한다.

- 문제와 완료 조건을 먼저 정한다.
- 현재 코드와 문서를 근거로 판단한다.
- 필요한 Master와 단계만 선택한다.
- 앞 단계 결과를 다음 단계 입력으로 사용한다.
- 실제 변경과 검증 결과를 분리해서 기록한다.
