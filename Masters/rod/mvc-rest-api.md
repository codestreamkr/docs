# 로드형의 Spring MVC·REST API

MVC 문서는 요청·응답 계약, Controller, 검증과 예외 처리가 중심인 작업에 사용한다.

## 사용하는 경우

외부 요청과 내부 서비스의 경계를 정한다.

- REST API의 요청과 응답 계약을 설계한다.
- Controller와 Service의 책임을 나눈다.
- 입력 검증과 공통 예외 처리를 구성한다.
- 상태 코드와 오류 응답 형식을 맞춘다.
- 페이징, 정렬과 필터 입력을 정리한다.
- API 변경의 하위 호환성을 확인한다.

## 필요한 입력

현재 API 계약과 유사 구현을 전달한다.

- Controller, Request·Response DTO, Service 위치
- 기존 성공·오류 응답 형식
- HTTP 메서드, 경로와 상태 코드 기준
- 입력 검증과 권한 조건
- 유지해야 하는 클라이언트 계약
- 관련 API 테스트

## 진행 기준

계약을 먼저 정하고 구현 계층을 연결한다.

1. 기존 Controller와 응답 형식을 확인한다.
2. 요청, 응답, 상태 코드와 오류 계약을 정한다.
3. Controller, Service와 데이터 접근 책임을 나눈다.
4. 검증과 예외 처리 위치를 맞춘다.
5. 정상, 검증 실패, 업무 오류와 권한 오류를 검증한다.

## 결과

클라이언트와 서버가 함께 사용할 계약을 남긴다.

- API 경로와 HTTP 메서드
- Request·Response DTO
- 상태 코드와 오류 응답
- Controller·Service 책임
- 검증과 공통 예외 처리
- API 테스트와 호환성 확인 사항

## 요청 예시

```text
로드형, 주문 취소 API를 추가해줘.
기존 ApiResponse와 오류 코드 형식은 유지하고
요청 검증, 권한, 중복 취소 응답까지 포함해줘.
```

```text
로드형, 목록 API에 작성자 이름과 검색 조건을 추가해줘.
기존 페이징 응답과 null 처리 기준을 유지하고 관련 테스트도 실행해줘.
```

## 확인 기준

API 변경은 호출자 관점에서 검증한다.

- Request와 Response가 Entity에 직접 의존하지 않는다.
- Controller에 업무 로직이 쌓이지 않는다.
- 상태 코드와 오류 형식이 기존 계약과 일치한다.
- 검증과 예외 처리가 한 기준으로 적용된다.
- 기존 호출자의 호환성 영향을 확인했다.
