# 기능 구현하고 검증하기

확정된 범위만 구현하고 영향받는 흐름을 검증해요.

## 흐름

```text
ct-plan-work      변경 범위와 완료 조건 확정      ← 계획이 없거나 범위가 불분명할 때
      ↓
ct-code-spring    확정된 범위 구현과 관련 테스트
      ↓
ct-qa-flow        영향받는 흐름과 실패 경로 검증  ← 별도 흐름 검증이 필요할 때
```

## 다음 단계로 넘어갈 기준

- 계획에서 유지할 API·데이터 계약과 완료 조건을 확정해요. 미정인 정책은 구현하지 않아요.
- 구현 중 계획 밖 변경이 필요하면 범위를 다시 확정해요.
- 구현 결과와 검증 결과를 구분해요. 권한, 중복 요청과 실패 복구 등 영향받는 경로를 확인해요.
- 검증하지 못한 범위와 남은 위험을 다음 작업에 전달해요.

## 다른 흐름을 쓸 때

- SQL 병목을 측정하고 개선안을 적용해야 하면 [04 느린 SQL 개선하기](./04-tune-sql.md)를 사용해요.
- 기존 구조를 병행 운영하며 옮겨야 하면 [05 구조 전환하기](./05-transition-structure.md)를 사용해요.
- 외부 공급자의 계약부터 확인해야 하면 [06 외부 서비스 연동하기](./06-integrate-external.md)를 사용해요.
